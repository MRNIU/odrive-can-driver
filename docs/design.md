# 0.1 驱动设计与实施

目标是可独立使用的 ODrive 驱动，包含真实收发、操作记录与反馈时效，不承担机械保护和产品控制策略。选择每节点一个固定容量 `Driver`：同一时间一个单帧操作。与异步运行时绑定或复制三套状态机相比，此设计允许 `no_std`、共享总线与不同调度器共用相同语义。

## 职责

| 文件 | 责任 |
|---|---|
| `src/driver.rs` | 命令/查询准备、操作身份、发送进展、期限、反馈缓存和结果 |
| `src/embedded_can.rs` | blocking 与 nb trait 的实际收发及原始错误传播 |
| `src/embassy.rs` | Embassy 原生异步收发；引脚、芯片和总线由应用配置 |
| `src/socketcan.rs` | Linux 非阻塞套接字客户端，不引入异步运行时 |
| `tests/` | 状态/时效/取消/错误与真实 Linux 套接字路径验证 |
| `examples/` | 最小消费方用法与可重复实板测试应用 |

## 操作与共享总线

准备操作先完成参数编码验证与时间检查；成功后分配操作身份。发送开始前记录 Dispatching，以 guard 的丢弃保存 Unknown。WouldBlock 只在后端明确未接收时返回可继续状态。写命令 Submitted 仅代表本地提交；查询 Submitted 等待同类反馈，报告 Observed。Heartbeat 永远不作为写命令 ACK。

未知发送阻止下一操作；调用方必须确认底层没有待发帧且不会迟到发送后，显式接收未知报告才能继续。这不是取消、回滚或设备停止证明。超时记录保留发送进展；不自动重试副作用。

调用方使用统一单调毫秒时钟。反馈保留自己的采样时刻，期限使用半开区间；过期帧不能反向完成操作。CANSimple 没有事务序号，同类周期帧、其他主机的查询回复或迟到回复无法证明归属，Observed 只说明提交后的观察。

共享总线应用统一读取并分发借用帧，统一提交发送。后端返回原始接收帧和被替换的发送帧，不吞掉别的设备帧；Classic、FD、RTR、错误通知保持区别。独占总线可直接使用后端推进同一 Driver。

## 实施与验收顺序

1. 独立审核上述设计，先写核心行为测试，再实现 core 与三个后端。
2. 完成中文 rustdoc、安装与示例、CI；在 Linux/devbox 完成相称的平台与 feature 检查、MSRV 和 package。
3. 在真实 Linux 验证 SocketCAN/vcan；用兼容实现验证 embedded-can 的收发/错误。软件注入单独标注。
4. 核对远程设备身份、固件、配置和适用运动参数；通过 H723 FDCAN2 与新 Embassy 后端执行真实主路径，结束显式 Idle 并读回。
5. 独立审查代码/API，修复具体问题并相称复验；提交推送、CI、dry-run、实际 crates.io 发布、docs.rs、tag 和 GitHub Release。

审查重点：取消发生于发送中、队列替换与共享帧保留、反馈陈旧与无事务号、未知结果的后续操作边界、误把本地提交视为设备动作完成。
